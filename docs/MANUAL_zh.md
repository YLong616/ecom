# 第一部分

## 1. 编写目的

### 1.1 面向读者

| 读者 | 关心什么 | 本文提供 |
|---|---|---|
| 使用/测试人员 | 怎么连、怎么发、怎么压测、日志在哪 | 第二部分的逐步操作说明与参数语义 |
| 维护/二次开发人员 | 功能边界、数据落点、扩展点 | 功能总览、配置文件与日志格式 |
| 评审/验收方 | 软件到底能做什么、怎么用 | 本文全篇；源码接口另见 `docs/API_REFERENCE_zh.md` |

### 1.2 编写要解决的问题

1. **讲清定位**：说明 eCOM 是什么、能做什么、在什么环境下运行，避免把它当作通用串口助手而误判其能力边界（尤其是压力模式与预期校验部分）。
2. **给可执行路径**：每个功能都给出「在哪点、按什么顺序点、参数怎么填、结果在哪看」，做到不读源码即可独立操作。
3. **固化关键参数语义**：例如「行间隔（单行优先于全局）」「响应超时（静默判定）」「结束条件（次数 / 时间，时间单位为小时）」「预期结果（空值也按 OK 比对）」。这些语义是压测结论可信的前提，不能靠猜。
4. **区分故障归属**：把「环境类故障」（端口被系统服务占用、权限不足、被其它程序打开）与「工具自身故障」分开，给出对应的处置方向，减少无效反馈。
5. **保证可复算**：说明日志与导出数据的格式与存放位置，使任何一轮压测都能由第三方按同一份配置复跑、按同一份日志核对。

### 1.3 覆盖范围

- **覆盖**：安装与启动、界面结构、全部用户可见功能的操作步骤与参数说明、配置文件与日志格式、使用约束、常见问题。
- **不覆盖**：
  - 源码级文件/方法/参数说明 → `docs/API_REFERENCE_zh.md`
  - 项目背景、架构、里程碑 → `docs/PROJECT_OVERVIEW_zh.md`、`PROGRESS.md`
  - Linux 串口环境深度排障（端口被系统服务占用等） → `docs/TROUBLESHOOT_zh.md`，也可在工具内「帮助 → Linux 串口排障手册」查看

## 2. 项目意义

### 2.1 现状问题

| 痛点 | 具体表现 |
|---|---|
| 调试与压测割裂 | 单条指令用一个串口助手，批量循环再另写脚本，两套工具、两套日志，结论无法合并 |
| 工具偏重、跨平台差 | 商业串口工具安装与运行依赖多，Windows/Linux 两套，难以裁剪出「只做这件事」的形态 |
| 压测不可复现 | 靠手工点击或临时脚本循环，轮次、间隔、异常判定口径每次都不一样，复盘无据可查 |
| 日志无结构 | 只留下原始字符流，没有「第几轮、哪一行、是否命中预期、异常几条」的信息 |
| 假阳性 | 没有预期校验时，即使设备返回 ERROR 也算「跑完了」，把问题漏过去 |
| 环境类故障重复踩 | 端口被系统服务接管、权限与锁文件等问题，换台机器就要重新排查一遍 |

### 2.2 本项目的价值

1. **一体化**：单条调试、AT 序列循环、压力测试（预期校验 + 统计 + 汇总）、文件下发、串口日志，收敛到一个工具，共用一套连接参数与日志格式。
2. **可复现**：压测的结束条件、间隔、超时、AT 序列、预期结果、check 规则可通过模板（`.xlsx`/`.csv`/`.txt`）导出与导入，同一份配置可在任意机器重跑。
3. **可留证**：日志按轮分段（`Runtimes N`），每行带毫秒级时间戳与 TX/RX 方向标记，且**输出框内容与日志文件逐字节一致**，可直接作为测试证据归档。
4. **判据明确**：每条命令可声明预期结果（默认 `OK`，支持多值与「包含/正则/全等」三种匹配模式）；**预期为空的命令行也按 `OK` 参与比对**，杜绝「没有校验就算通过」的假阳性；再叠加自定义 check 规则（如设备异常重启关键字），把偶发异常显性化。
5. **轻量跨平台**：Tkinter（Python 标准库）+ pyserial，Windows 与 Linux 同一份源码；`pip install .` 后 `ecom start` 即可运行；只有 `.xlsx` 模板/数据才需要 openpyxl，缺少时 csv/txt 功能不受影响。
6. **抗环境异常**：串口被拔出后自动断开并把界面复位；检测到端口被系统服务占用时主动提示并给出手册入口；排障手册内嵌进工具，SSH 无图形界面时也可用 `ecom help` 查阅。
7. **可维护**：模块按职责拆分（串口核心 / 编解码 / 面板 / 压测模型 / 导入导出 / 日志 / 配置 / 多语言），并配有回归测试，便于后续扩展。

### 2.3 典型适用场景

- 设备上电与联网流程调试：逐条发 AT 指令、观察响应、同步抓日志；
- 稳定性压测：按固定的 AT 序列循环 N 轮或运行 N 小时，统计异常条数与异常关键字；
- 版本回归：同一份 AT 序列与预期，横向比较不同软件版本的异常数；
- 现场问题复现：把现场的 AT 序列与日志带回，用相同配置在本地复跑。

# 第二部分 系统概述

## 3. 系统定位与运行形态

- **形态**：桌面 GUI 应用（单个主窗口），附带一个命令行入口（安装后为 `ecom`）。
- **单窗口双模式**：AT 模式与压力模式在同一窗口内切换；两种模式各自持有**独立的串口连接**，互不影响（压力模式打开失败不会打断 AT 模式的连接）。
- **无服务端、无网络依赖**：所有数据都在本机（除可选的 pip 安装过程）；工具不上传任何数据。
- **语言**：界面支持中文 / English 实时切换。

## 4. 运行环境与安装

### 4.1 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows 10+ / Linux 主流发行版 | 需桌面环境（GUI） |
| Python | ≥ 3.8 | Windows 用官方安装器；Linux 用发行版包 |
| tkinter | 系统级依赖 | **pip 无法安装**，Linux 需系统包管理器单独装 |
| pyserial | ≥ 3.5 | 串口通信 |
| openpyxl | ≥ 3.0 | 仅 `.xlsx` 模板/导入/导出需要；缺失时 csv/txt 仍可用 |

Linux 安装 tkinter：

```bash
sudo apt install python3-tk        # Ubuntu / Debian
sudo dnf install python3-tkinter   # Fedora
sudo pacman -S tk                  # Arch
sudo zypper install python3-tk     # openSUSE
```

### 4.2 安装与启动

| 方式 | 命令 | 场景 |
|---|---|---|
| 源码直接运行 | `python main.py` | 开发/调试 |
| 安装为命令 | `pip install .` 然后 `ecom start` | 日常使用 |
| 查看版本 | `ecom --version` | 确认安装版本 |
| 查阅排障手册 | `ecom help` / `ecom help -l en` | 无图形界面（SSH）时也可用 |

### 4.3 退出

- 关闭窗口（标题栏 "×"）：会保存配置、停止日志、关闭串口后退出；
- 或终端 `Ctrl+C`（仅源码运行时有效）。

## 7. 功能使用说明

### 7.1 连接串口（F1 / F4 / F14）

**操作步骤**

1. 点「刷新」，端口下拉中会出现本机串口，显示形式为「设备名 + 设备全名」，例如 `COM78  USB Serial Port (COM78)`；Linux 下为 `/dev/ttyUSB0` 等。
2. 依次选择波特率、数据位、停止位、校验位、流控。
3. 如需控制 DTR / RTS 引脚，勾选对应的「DTR」「RTS」（**勾选 = 拉低该引脚**）；勾选状态在打开串口后立即生效，运行中改动也即时生效。
4. 点「打开串口」。按钮变为「关闭串口」，状态栏圆点点亮并显示「已连接」，右侧显示当前连接参数摘要。
5. 结束使用点「关闭串口」，或直接关闭窗口（会自动关闭）。

**可选项与默认值**

| 参数 | 可选项 | 默认值 |
|---|---|---|
| 波特率 | 9600 / 19200 / 38400 / 57600 / 115200 / 230400 / 460800 / 921600 | 115200 |
| 数据位 | 8 / 7 / 6 / 5 | 8 |
| 停止位 | 1 / 1.5 / 2 | 1 |
| 校验位 | None (N) / Even (E) / Odd (O) / Mark (M) / Space (S) | None (N) |
| 流控 | None / RTS/CTS / XON/XOFF | None |

**注意事项**

- 打开失败时，输出区会给出原因（如「[错误] 打开串口失败: …」），常见原因：端口被其它程序占用、波特率与设备不符、Linux 下无读写权限（需加入 `dialout` 组）。
- **热插拔**：串口被拔出后，工具约 0.6 秒内自动关闭连接、清除输入区状态，并把按钮复位为「打开串口」，端口下拉中剔除已失效的端口，状态栏提示「设备已断开（串口被移除），已自动关闭连接」。
- Linux 下若检测到端口正被系统串口服务（ModemManager）占用，输出区会给出提示「…请通过『帮助 → Linux 串口排障手册』查看解决方法」，处理办法见该手册。
- 虚拟端口（含 `:` 的端口名，如 `loop://`）不参与热插拔探测，便于无硬件自测。

### 7.2 手动收发与显示控制（F2 / F3 / F11 / F15）

**操作步骤**

1. 在「输入（发送）」框中键入内容（可多行）。
2. 选择「类型」与「后缀」：
   - **类型**：`ASCII`（文本）、`HEX`（十六进制串，如 `41 54 0D 0A`）、`DEC`（十进制字节序列）、`BIN`（二进制位串）；
   - **后缀**（send-on-enter）：`None` / `CR` / `LF` / `CR-LF`（默认）/ `SPACE` / `STX-ETX` / `NULL`。
3. 点「发送」或直接按 `Enter`（输入框内回车即发送，适合单行指令）。
4. 在「输出（接收）」框中查看：`TX` 为发出内容，`RX` 为收到内容，每行前带时间戳 `[YYYY-MM-DD_HH:MM:SS:mmm]`。
5. 「显示选项」勾选控制显示形态：时间戳、方向（TX/RX 标记）、显示 `\r\n`（把控制字符转义展示）、接收 HEX（把收到的数据以十六进制展示）。
6. 「清空输出」「清空输入」分别清屏；「清零计数」把 TX/RX 字节计数归零。

**收发显示规则**

- 接收采用**静默聚合 + 按行渲染**：连续字节先累积，静默 120 ms 或遇到换行即渲染；因此一条设备响应不会被拆成多行碎片，也不会被后续发送回显插在中间。
- 输出框与日志文件内容**逐字节一致**（同一行文本同时写入两处）。
- TX 用蓝色、RX 用绿色显示，便于区分。

**复制与字号（F15）**

| 操作 | 方式 |
|---|---|
| 复制选中 | 选中后右键 →「复制」，或 `Ctrl+C` |
| 全选 | 右键 →「全选」，或 `Ctrl+A` |
| 复制全部 | 右键 →「复制全部」（提示「已复制 N 字符到剪贴板」） |
| 缩放字体 | 输出框/输入框内 `Ctrl+滚轮`（字号范围 8–28，两个框各自独立） |
| 输入框常用编辑 | `Ctrl+Z` 撤销（可撤 2000 步）、`Ctrl+←/→` 按词移动光标 |

> 「复制全部」写入剪贴板后会在输入区与弹窗中提示「已复制 N 字符到剪贴板」；内容超过 3,000,000 字符时会先提示可能无法完整承载，建议改用「Log 保存」落盘后再处理，或分段复制。

### 7.3 串口日志（F5）

1. 点「选择Log文件…」指定保存路径（可任意文件名与扩展名，支持中文/日文/俄文等 Unicode 名称）。
2. 点「开始记录Log」，按钮变为「停止记录Log」，右侧状态显示「记录Log」。
3. 此后所有 TX/RX 行（含时间戳、方向）实时追加写入该文件；点「停止记录Log」结束。
4. 关闭窗口时会自动停止记录。

**注意事项**

- 日志行格式与输出框完全一致：`[时间戳]  TX/RX  正文`，每行独立时间戳；
- 路径输入框较窄时鼠标悬停可弹出完整路径提示；切换语言不会影响已选路径。

### 7.4 AT list 与命令组（F6）

**AT list 是什么**：右栏的可编辑命令表，是「批量/循环发送」的数据源。每页固定显示 **22 行**（含空行占位，行位不因内容为空而消失）。

**每行字段**

| 列 | 含义 |
|---|---|
| 序号 | 当前页码内的行号（1–22，翻页后重新从 1 开始） |
| ☑（第 1 列复选框） | 是否参与「循环运行」（勾选才发送） |
| 命令输入框 | 可直接编辑的命令文本 |
| HEX（复选框） | 勾选则本条按 HEX 发送 |
| Enter（复选框） | 勾选则本条追加 `CR-LF` 后缀 |
| 发送（按钮） | 单独发送本行（与是否勾选无关） |

**表头三个全选控件**

- 「全选」：本页所有行的勾选状态一次置为相同值；
- 「HEX全选」「Enter全选」：本页所有行的 HEX / Enter 列整体勾选或取消。

**分页**

| 按钮 | 作用 |
|---|---|
| 上一页 / 下一页 | 翻页（翻译前先自动保存当前页编辑内容，不会丢改动） |
| 页码输入框 + 跳转 | 输入页码后回车或点「跳转」直达；页码非法时提示「页码无效」 |
| 添加下一页 | 在末尾追加 22 行空行并跳转到新页 |
| 第 x / n 页 | 显示当前页与总页数（按总行数计算，含空行） |

**命令组（配置文件）**

1. 顶部下拉框列出 `configs/` 下所有命令组；首次启动默认选中第一个（通常为 `config`）。下拉可直接选择已有组，也可**直接输入新名称**。
2. 点「保存」：把当前全部非空命令行写入 `configs/<组名>.json`（同名直接覆盖，新名即新建）。
3. 从下拉选择其它组即自动加载（行位、勾选、HEX/Enter 状态一并恢复）。
4. 「一键清空」清空所有输入框中的命令文本，但**保留勾选与 HEX/Enter 状态**（需二次确认）。
5. 「删除」删除命名的命令组文件（弹确认框，取消则不删）。

命令组文件内容形如：

```json
[
  {"text": "AT", "hex": false, "enter": true},
  {"text": "AT+CGMR", "hex": false, "enter": true}
]
```

### 7.5 循环运行（F7）

**操作步骤**

1. 在 AT list 中填写命令并对要参与运行的行打勾；
2. 设置「循环次数」（范围 0–9999）与「间隔(ms)」（范围 0–3600000，默认 300）；
3. 点「Run」，按行序循环发送；按钮文字实时变为当前轮次数字（如 `2`），结束后恢复为 `Run`；
4. 需要中止时点「Stop」（立即停止，不再排下一轮）。

**注意事项**

- **循环次数填 0 或留空时按 1 次执行**（防止误触发不可控的无限循环）；
- 未勾选任何行时点 Run 会提示「请先选中一条命令」；
- 空白命令行会被跳过（不发送），但仍占用轮次计数位置。

### 7.6 压力模式（F8）

切换到压力模式：点顶部「串口模式切换」→ 选择「压力模式」。压力模式**使用自己的串口连接**（左列「串口配置（压测）」需单独打开），与 AT 模式的连接互不干扰。

#### 7.6.1 压测名称

- 默认 `压力测试1`；点「修改」→ 输入框可编辑、按钮变「保存」→ 点「保存」锁定。
- 名称会写入 AT Log 头部行与汇总块。

#### 7.6.2 压测配置

| 配置项 | 可选/范围 | 默认 | 语义 |
|---|---|---|---|
| 结束条件 | 次数 / 时间（二选一，单选按钮） | 次数 | 次数=跑满 N 轮；时间=运行满 N 小时 |
| 次数 | 1–9999 | 1 | 结束条件为「次数」时生效 |
| 时间 | 数值（单位：**小时**） | 1 | 结束条件为「时间」时生效；可填小数，如 `0.5` = 30 分钟 |
| 行间隔(ms) | 0–3600000 | 300 | **全局默认行间隔**；单行设置了间隔时以单行为准 |
| 响应超时(ms) | 100–600000 | 2000 | 收到数据后静默超过该时长，即认为本次响应结束，开始做预期比对 |
| AT Log | 文件路径 | 空 | 压测运行日志（含每行 TX/RX、轮次标记、汇总） |
| DOS Log | 文件路径 | 空 | 只记录被判定为异常/命中规则的行 |

#### 7.6.3 压测 AT list

表格列（10 列）：`#` | ☑ | `AT命令` | `HEX` | `Enter` | `类型` | `后缀` | `间隔(ms)` | `预期结果` | `编辑`。

- **每页 8 行**，可横向滚动查看右侧列；分页操作与 AT list 相同（上一页 / 页码跳转 / 下一页 / 添加下一页）。
- **表头批量控件**：`HEX` / `Enter` 列表头是「整列全选」复选框；`类型` / `后缀` 列表头是下拉框，选择后**批量设置整页该列**（鼠标悬停有说明「批量设置整列发送类型 / 后缀」）。
- **HEX / Enter 与 类型 / 后缀 双向联动**：勾 HEX ⇔ 类型置 `HEX`；勾 Enter ⇔ 后缀置 `CR-LF`。
- **间隔列**：默认显示 300；填值即「该行自己的间隔」，**留空（或非法值）表示使用全局行间隔**。
- **预期结果列**：默认 `OK`；点「编辑」打开对话框，可写多条预期（**换行或 `|` 分隔，命中任意一条即通过**），并选择匹配模式：`包含`（默认）/ `正则` / `全等`。
  对话框分上下两块：**上方窄条是「匹配示例」**，随所选匹配模式（包含 / 正则 / 全等）动态变化，给出「实际接收内容 → 预期这么写 → 命中 / 不命中」的对照，并点明各模式的写法要点：包含只按字面子串比对（**预期里不要写 `\r\n`**）、正则里 `\r\n` 与 `\s` 是转义（跨行需 `(?m)` / `(?s)`，且预期里不能出现真实换行或 `|`）、全等要求逐字符相同且**只适合单行响应**；**下方宽区才是预期输入框**（可随窗口拉伸）。
  **对话框下半部分还有一个「测试」区**：测试命令框默认带出该行 AT 命令（可改），点「测试」即按**该行的发送类型/后缀**发出
  （HEX 行按 HEX、勾了 Enter 按 CR-LF；下方一行实时显示「发送方式 + 串口」，未开串口时不发送），
  然后把模组返回原样显示在结果框里（可滚动、可右键复制/全选），并用**当前匹配模式**把「返回结果」与上方预期即时比对：
  **命中绿色加粗**（结论里带上模式名，如「匹配成功（包含 · 预期：OK）」）、**未命中红色加粗**；
  右侧「用返回填充预期」可把刚收到的返回整段填进预期框（**全等模式**尤其实用），确认后再点「保存」才落盘。
  对话框底部两个按钮两种底色：**「保存」主色蓝、「退出」中性灰**（退出不丢已保存内容，故不用红）。
  判定时机：收到数据后静默 120 ms 视为一帧结束，或到达压测配置里的「响应超时」为止；
  期间**串口掉线/异常会立刻结束测试并给出原因**（不用干等超时）；命令与预期都支持宏 `${name}`。
- 每行勾选状态决定是否参与压测；未勾选或命令为空的行不发送。

#### 7.6.4 自定义 check 规则

- 列：`启用` | `规则名` | `触发关键字` | `记录目标` | `-`（删除）。
- **记录目标**：`AT Log` / `DOS Log` / `两者`。
- 每页 3 条，可「添加规则」「上一页 / 下一页」。
- 内置两条示例规则（**默认关闭**，可按需启用或修改）：
  1. 规则名「模组异常重启」，触发关键字 `RDY`；
  2. 规则名「响应含ERROR」，触发关键字 `ERROR`。
- 命中的行会计入「异常」统计，并按记录目标写入对应日志。

#### 7.6.5 开始 / 停止与运行统计

1. 确认已在「串口配置（压测）」中打开串口，并已勾选至少一行命令，否则点「开始」会分别提示「请先打开串口」「请先勾选至少一行」。
2. 点「开始」（绿色）：按钮变为当前轮次数字并置为不可点，同时开始写 AT/DOS 日志；「停止」为可点状态。
3. 运行中「运行统计」实时刷新：已发送、异常、当前行、测试时长、总运行次数、脚本运行时间段。
4. 点「停止」（红色）或达成结束条件后自动停止，并输出汇总块。
5. 切换回 AT 模式时，正在运行的压测会被自动停止（串口连接不关闭）。

#### 7.6.6 运行日志结构

```
=== 压力名称:压力测试1 | 次数=5 | 行间隔(ms):300 | 响应超时(ms):2000 ===
=================== Runtimes 1 ===================
[2026-08-26_13:47:23:903]  TX  AT
[2026-08-26_13:47:24:019]  RX  AT
[2026-08-26_13:47:24:022]  RX  OK
=================== Runtimes 2 ===================
…
=================== Runtimes 5 ===================
…
== 汇总 ==
压力名称: 压力测试1
测试时长: 0.0H
运行时间: 2026-08-26 13:47:23.900387~2026-08-26 13:47:28.197361
总运行次数: 5
已发送: 10
异常: 0
```

- **第 1 行（`=== … ===`）**：本次压测的配置快照（名称、结束条件、全局行间隔、响应超时）；
- **`Runtimes N`**：第 N 轮开始的分隔标记，每轮一条，便于逐轮核对；
- **`== 汇总 ==`**：测试时长（小时，1 位小数）、脚本运行时间段、总运行次数、已发送行数、异常条数；
- 异常判定 = 预期不匹配 或 命中启用的 check 规则。

### 7.12 宏定义（参数自定义，F16）

顶部 →「宏定义」打开**独立窗口**（居中于主窗口，不改动主界面布局）：上面一句说明 + `新增` / `保存` / `一键删除`，下面是表格（**只有横线**）：多选框 | 宏名称 key（可编辑）| 宏值 value（可编辑）| 长度 | 编辑 | 删除，底部为分页。

**值的两种写法**（长度列实时显示 value 展开后的 **UTF-8 字节数**）：

| 写法 | 语义 | 示例 | 长度 |
|---|---|---|---|
| 字面量 + `*N`（默认） | `*` 后是整数则把前面内容重复 N 次；否则 `*` 按普通字符 | `12345*10` | 50 byte |
| 同上 | 不含 `*N` 时就是原文 | `123456` / `12345-1` | 6 / 7 byte |
| `=` 开头 | 受限 Python 表达式（字面量、`+ - * // % **`、`str/int/len/join/repeat/upper/lower/…`） | `=str(1500)+',x'` | 6 byte |

**宏名规则**：不限字符 —— 数字开头（`1pkg`）、连字符（`data-2`）、中文（`数据包`）、点号都可以；**但不能含空格**（`${a b}` 与 `${ab}` 肉眼极易看混：界面会即时红字提示并拦住保存），也不能含右花括号 `}` 或换行（引用形式 `${...}` 以 `}` 结束）。

**表内对齐**：表头与数据行在同一网格里，列宽一致（长度列右对齐、操作列正对按钮）。
**搜索**：工具条右侧「搜索」框支持**模糊匹配** —— 按宏名子序列（`dta` 能命中 `data`），也匹配宏值内容；**只影响显示、不影响保存范围**（保存仍是全部），搜索期间状态栏显示 `匹配 n/总数`，「×」清空，点「新增」会自动清空搜索。
**用法**：在命令里写 `${name}`。例如宏表里 `data = 1234567890*150`（长度列会显示 `1500 byte`），命令写 `AT+TCPSEND=1500,"${data}"`。展开发生在**发送时**，界面与配置里始终保留 `${name}` 形式。

> 注意：`${...}` 只替换**宏表里定义的宏**，命令行里**不能**写表达式（如 `${len(data)}` 不算宏，会原样发出）。要凑长度就用长度列读数字，或再定义一条宏（如 `data_len = 1500`）写成 `AT+TCPSEND=${data_len},"${data}"`：不过它**不会自动跟着 `data` 变**，改数据后记得同步改 `data_len`。

**生效范围**：AT 模式输入框发送、AT list 单行/循环发送、压力模式 AT list 与「预期结果 → 测试」的测试命令；**文件发送不展开**（按文件原文下发）。

**安全与边界**：表达式用自写 AST 求值器（**不是 eval**），禁止 `import`、属性访问、下标、变量引用与推导式；结果上限 1 MiB，字符串重复会先算长度再构造（`='x'*10**9` 直接拒绝）。

**未知宏/值有误**：发送前会被拦下（AT 模式在输入框红字提示、压力模式在输出区提示），**不会把错误命令打进模组**。

**保存语义**：只有点「保存」才写入 `~/.ecom/config.json` 的 `macros`；不保存关闭即作废（因此删除行、一键删除都不做二次确认）。
花括号 `{`/`}` 就是普通字符（JSON 载荷无需转义）；要写字面 `$` 时用 `$$`。
## 8. 数据与配置文件

### 8.1 全局配置 `~/.ecom/config.json`

| 时机 | 写入内容 |
|---|---|
| 关闭窗口时 | 串口参数（端口/波特率/数据位/停止位/校验位/流控）、显示选项（时间戳/方向/CRLF/HEX）、发送类型与后缀、当前语言 |
| 选择 Log 路径时 | `log.path` |
| 宏定义窗口点「保存」时 | `macros`（`[{key, value}, …]`） |

> 该文件位于用户家目录、跨项目共享；删除后下次启动恢复默认值。压力模式的配置目前**不写入**该文件（见 9.9）。

### 8.2 AT 命令组 `configs/<组名>.json`

- 位置：项目根目录下的 `configs/`（开发运行时）；
- 打包安装后若项目目录不可写，回退到 `~/.ecom/configs/`；
- 每个文件 = 一个命令组；格式见 7.4。

### 8.3 日志与导出文件

| 文件 | 产生方式 | 内容 |
|---|---|---|
| AT Log（模式一） | 「Log 保存」行 | 全部 TX/RX 行，与输出框逐字节一致 |
| AT Log（压力模式） | 压测配置中的 AT Log | 头部配置行 + `Runtimes N` 分段 + 全部 TX/RX + 汇总 |
| DOS Log（压力模式） | 压测配置中的 DOS Log | 异常行（预期不匹配 / 命中 check 规则） |
| `stress_data.*` / `stress_template.*` | 压测导入导出按钮 | 9 列 AT list 数据 / 模板 |

### 8.4 屏幕输出行格式

```
[YYYY-MM-DD_HH:MM:SS:mmm]  TX/RX  正文
```

- 时间戳可通过「时间戳」复选框关闭；方向标记可通过「方向」关闭；
- 正文中的控制字符默认转义显示（`\r\n`），关闭该选项后按原样（可能造成换行）显示。

## 9. 使用约束与注意事项

1. **发送类型与内容必须匹配**：类型选 `HEX`/`DEC`/`BIN` 时，输入内容必须是对应的合法字面量；不匹配时输出区提示「发送内容与发送类型不符，无法解析：…」，不会崩溃。
2. **超大文本剪贴板**：文本超过 3,000,000 字符时，「复制全部」会提示可能无法完整承载，建议先用「Log 保存」把内容落盘，或分段复制。
3. **行间隔的真实语义是「该行执行完成后的等待」**：压测中，某行设置了 `interval_ms`，则在其执行完毕后等待该时长再进入下一行；未设置（留空）则使用全局「行间隔(ms)」。
4. **结束条件的单位是小时**：时间为小数小时（`0.5` = 30 分钟），不是分钟。
5. **预期结果为空也参与比对**：勾选且命令非空的行，若预期留空，将按默认 `OK` 参与比对；要「不校验」，请让该行不参与勾选。
6. **运行中不要改动配置**：压测运行中，「开始」按钮被占用显示轮次；如需修改配置请先「停止」。
7. **窗口可自由缩小**：最小到 560×420；缩到比内容还小时会出现**横/纵滚动条**，用滚轮（Shift+滚轮横向）或拖动滚动条查看，内容不会被裁掉。指针停在输出框/AT list 这类自带滚动的控件上时，滚轮只滚它们，不滚整页。
8. **切换模式会停止压测**：从压力模式切回 AT 模式时，正在运行的压测会被停止（连接保留）。
8. **语言切换的时效**：主界面与压力面板的静态文字随切换刷新；个别图标/工具提示文本可能在切换后保留原语言，重启即可完全一致。
9. **压力模式配置不落盘**：压测名称、结束条件、AT list、check 规则等**不会**写入配置文件，关闭窗口后不保留；需要复用请用「导出当前数据」保存为文件，下次「导入数据」恢复。
10. **Linux 环境依赖**：需系统级 `python3-tk`；当前用户需有串口读写权限（通常在 `dialout` 组）；若端口被系统串口服务占用，表现为「命令发得出去、收不到回复」，处置见排障手册。
11. **源码加密环境不影响使用**：在部署了透明加密（E-SafeNet）的机器上，`ecom/*.py` 可能以密文形态落盘。运行时不受影响，但**二次开发时常规文本工具读到的是密文**，必须用被放行的 Python 进程做字节级替换（详见 `PROGRESS.md`「关键决策」）。使用本工具无需关心此点。
12. **文档/代码的一处不一致（已知瑕疵）**：`ecom/config.py` 中 `stress.time` 的注释写的是「单位：分钟」，而实际界面与计算均为**小时**。以本文与界面为准；该字段当前未被读写，不影响运行。

## 10. 常见问题速查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 打不开串口 | 端口被其它程序占用 / 波特率不符 / Linux 无权限 | 关闭占用程序；核对波特率；加入 `dialout` 组后重新登录 |
| 发命令没回复 | 端口被系统串口服务接管 / DTR·RTS 电平不对 / 设备未就绪 | 看是否弹出占用提示 → 打开「帮助 → Linux 串口排障手册」；调整 DTR/RTS 勾选；确认设备供电与启动状态 |
| 接收内容被拆成多行/乱序 | 设备分片发送导致 | 属正常分帧；工具已按静默 120 ms 聚合并按行渲染，如需查看原始字节可勾选「接收 HEX」 |
| 输出框有内容但日志文件为空 | 未点「开始记录Log」/ 未选路径 | 选路径后点「开始记录Log」，状态显示「记录Log」 |
| 循环 Run 只发了一次 | 「循环次数」为 0 或留空 | 填写目标轮次（0 按 1 次执行） |
| 压测报告「异常」不为 0 | 预期不匹配 / 命中 check 规则 | 查看 DOS Log 中标记为「预期不匹配」的行；核对预期文本与匹配模式 |
| 压测点开始无反应 | 未打开压测串口 / 未勾选行 | 先「打开串口」，再勾选至少一行命令 |
| 压测结束后配置丢失 | 压力模式配置不落盘 | 使用「导出当前数据」保存；下次「导入数据」恢复 |
| 语言切换后个别文字没变 | 动态控件未登记刷新 | 重启工具；如需长期正确可提交给维护者登记该控件 |
| 端口列表为空 | 设备未连接/驱动未安装/Linux 权限 | 检查设备管理器或 `ls /dev/tty*`；确认驱动与权限后点「刷新」 |

## 附录 B 术语
