# eCOM 已知限制与遗留项（Known Issues）

> 记录当前版本已知的限制、未决问题与开发注意事项。**本列表随修复迭代更新**；修复并验证后应从本节移除。

---

## 1. 遗留未决项

### 1.1 压力面板语言切换不随动（未修复）

- **现象**：通过菜单「语言」切换中/英文后，主界面（app 层）文字会刷新，但**压力模式（stress_panel）内部分新增/复杂控件的文字不随动**，仍停留在切换前的语言。
- **根因**：`stress_panel` 的控件未接入 `EcomApp._register` 语言刷新机制（语言切换只刷新了登记过的控件），压力面板文字未在 `_apply_language` 中统一重刷。
- **影响**：中英混排，体验不一致。属**已知遗留项**。
- **为何未修**：接入 `_register` 需对压力面板大量控件逐一登记并在 `_apply_language` 中刷新，改动面大、易引入回归；本轮未强行修。
- **规避/后续**：如需彻底修复，建议为 `StressPanel` 增加一个 `refresh_text()` 方法（遍历其自身控件按 `_t` 重刷），并在 `app._apply_language` 中显式调用；补上前先用单一语言运行。

### 1.2 旧版本备份目录未清理

- `xbak/` 目录为更早版本备份，**暂留未动**。非源码，不影响运行；如确认不再需要可删除以减小仓库体积。

## 2. 环境限制（开发/部署）

### 2.1 源码被安全软件加密（E-SafeNet / DLP）

- **现象**：在部分企业环境，`ecom/*.py` 会被安全软件（E-SafeNet/DLP）加密。用普通文本工具或 `read_file`/`edit_file` 读取时会得到**密文或被截断的内容**——实测 `app.py` 被读为截断的 **237 行密文**（磁盘真身 **746 行**）、`file_panel.py` 被读为 **29 行密文**（真身 **127 行**）。
- **根因**：DLP 按进程白名单透明加解密；只有白名单进程（如 `python389.exe`）才能读到明文。
- **影响**：**不能**直接依赖文本编辑器/读文件工具进行创建或修改；否则要么读到密文、要么写回破坏加密文件。
- **正确的开发方式**：
  1. 用 Python（白名单进程）以 `open(..., encoding='utf-8')` 读明文；
  2. 做**字节级字符串替换**后写回；
  3. `python -m compileall -q ecom` 校验语法；
  4. `python -m unittest discover tests` 跑回归。
- **注意**：`*.bak_*` 文件是历史备份，**不是源码，勿修改**。

### 2.2 真实 GUI 截图自动不可靠

- **现象**：自动化截取 eCOM 真实窗口（`python main.py` 运行中）常得到**空白/近乎纯色**图像（曾测得平均亮度 ≈251.6），因为桌面级截图被上层遮挡，且依赖窗口在前台。
- **影响**：文档中的界面截图难以由工具自动生成，需人工在本地运行后补拍（见用户指南 `USER_GUIDE_*.md` 的「截图需求清单」）。
- **规避**：维护者在真实环境运行后按清单补图即可；当前文档以 ASCII 布局图 + 原型渲染图示意。

## 3. 行为 / 边界限制

### 3.1 压测结束条件仅两种

- 「结束方式」仅支持 **按次数** 或 **按时间**（到 N 分钟）二选一；没有"无限运行"选项（可随时点「停止」手动结束）。
- 需**至少完成一轮**才会输出 `== 汇总 ==`；若一轮尚未跑完或未满足结束条件就停止，仅输出已执行片段。

### 3.2 自定义 check 规则为子串匹配

- 规则关键字使用**简单子串包含**（`keyword in response_text`），**不支持正则**；且规则默认关闭，需要时手动启用。
- 命中规则即计入 `errors`（异常），并把该响应记录到指定目标（AT / DOS / BOTH）。

### 3.3 预期结果匹配的降级行为

- 匹配模式 `regex` 遇到**非法正则**时退化为 `contains`（包含匹配），不报错。
- `contains` / `exact` 分别为子串包含、去除首尾空白后的精确相等。
- 预期结果为空的行会**按默认 `OK` 参与对比**（`StressRow.expected` 默认 `OK`；`_collect_rows` 对空预期兜底补 `OK`），因此不会出现"预期为空就跳过校验"的情况。

### 3.4 行间隔语义

- AT list 每行可单独设 `interval_ms`：**>0 时优先于全局行间隔；=0 回落全局「行间隔(ms)」**。
- 该间隔作用于"该行执行完成后"的等待，即「上行 → 等待 → 下行」中的等待。

### 3.5 端口依赖与虚拟端口

- 端口枚举依赖 `pyserial` 的 `list_ports`；无硬件时可在端口下拉/输入框手动填 `loop://` 等虚拟端口（`serial_for_url` 支持）用于自测。
- 部分设备可能需要正确勾选 DTR/RTS 才能唤醒。

### 3.6 布局对窗口尺寸的依赖

- 界面采用固定权重分栏（左约 2/3、右约 1/3），窗口过窄时右侧/列举可能出现横向滚动或文字截断；建议使用默认窗口尺寸（约 1000×850）或适度放大。

## 4. 数据/兼容性说明

- 配置存于 `~/.ecom/config.json`（JSON，`ensure_ascii=False, indent=2`），跨项目共享。
- AT list 导出/导入用 **CSV**：写 `utf-8-sig`（带 BOM，Windows Excel 双击不乱码、Linux 亦可读），读兼容带/不带 BOM。
- 旧配置中的 `send.suffix == "CRLF"` 会在加载时自动迁移为 `"CR-LF"`。
- 日志与输出框**逐字节一致**：`[2026-08-26_13:47:23:903]  TX  AT+QGMR`，方便直接对拍。

## 5. 维护者清单（开发前必读）

1. **先读 `PROGRESS.md`**（唯一真相源）恢复上下文，重点看「下一步 / 待办 / 未决问题」。
2. 修改源码**必须用 Python 脚本**做字节级替换（E-SafeNet），禁止用文本编辑器直接保存。
3. 每次改动后：`py_compile` 语法校验 + `unittest discover tests` 回归 + 虚拟端口冒烟。
4. 涉及双语界面的改动，尽量把新键加入 `i18n.py` 并接入 `_register`/刷新，避免新增语言不随动项。
